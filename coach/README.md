# コーチ手順書

このリポジトリは筋トレ記録アプリのデータ置き場です。Claude の定期タスクはこの手順に従います。

- `data.json` … アプリが自動保存する記録（形式は kintorekiroku リポジトリの設計書 §4）。**読むだけ。絶対に書き換えない。**
- `feedback.json` … コーチの出力。アプリのホーム画面「コーチより」に表示される。

日付はすべて Asia/Tokyo。週は月曜始まり。

## 1. 週次レビュー（毎週日曜 21:00）

1. `data.json` を読む。なければ何もせず終了。
2. 次の観点で、直近4週間（今週を含む28日）とその前の4週間を比べる。
   - 伸び：種目ごとの「その回の最高値」（最も強い負荷のセットの中での最大回数・秒数）、負荷アップ（バンドが強くなった・kg が増えた）、`nextId` の段階に進んだか
   - 停滞：同じ負荷で最高値が2回続けて下がった種目
   - 偏り：今週の部位別セット数（`exercises[].part`）で少ない部位
   - 休み：`skips` の理由の傾向（例：「疲れ」が続く曜日）
   - メモ：`sessions[].note` に書かれた体調
   - 体：`body` の体重・ウエストの7日平均の推移
   - 継続：週の目標日数（`settings.weeklyGoal`）の達成状況
3. `feedback.json` を次の形で上書きする（`date` は今日）。
   ```json
   { "date": "2026-10-25", "kind": "weekly",
     "summary": "1〜2文",
     "good": ["伸びた点"],
     "next": ["来週やること"] }
   ```
   - `good` と `next` は各最大3項目。1項目1文、40字以内。
   - `next` は具体的に（種目名・回数・バンド名・セット数）。目標範囲 `min`〜`max` と、持っているバンド `bands` の中で提案する。
   - 記録が少ない週も責めない。「軽めの日」や休みも続けている証拠として扱う。
   - 器具は自重とトレーニングバンドが中心。持っていない器具を前提にしない。
4. コミットメッセージ `coach: weekly {date}` でコミットし、既定ブランチに push する。
5. 終了時の要約に `summary` と同じ文を書く（Claude アプリの通知に出る）。

## 2. 水曜チェック（毎週水曜 19:00）

1. `data.json` を読む。なければ何もせず終了。
2. 今週の月曜〜今日（水曜）に `sessions` が1件でもあれば、何もせず終了（通知に出す要約も「今週は記録あり」の1行だけ）。
3. 1件もなければ `feedback.json` を次の形で上書きし、`coach: nudge {date}` でコミットして push する。
   ```json
   { "date": "2026-10-22", "kind": "nudge",
     "summary": "今週はまだ記録がありません。今日は「軽めの日」だけでもどうでしょう。5分で終わります。" }
   ```
4. 終了時の要約に同じ `summary` を書く。

## してはいけないこと

- `data.json` の変更・削除
- `feedback.json` と、この README 以外のファイルの追加・変更
- 責める表現（「サボり」「怠け」など）

# コーチ手順書（コーチ便）

このリポジトリは筋トレ記録アプリのデータ置き場です。Claude の定期タスク（毎日 07:30 前後）はこの手順に従います。

- `data.json` … アプリが自動保存する記録。**読むだけ。絶対に書き換えない。**
- `posts.json` … コーチ便。アプリのホーム「新着」に出る。**このタスクが書く。**
- `topics.json` … これまでに扱った読み物のテーマ・要点・出典。重複を避けるために使う。**このタスクが書く。**

日付と時刻はすべて Asia/Tokyo。週は月曜始まり。

## データの読み方（要点）
- `sessions[]`：`date`、`light`（軽めの日）、`note`（メモ）、`toCoach`（true なら返信してほしいメモ）、`sets[]`
- `sets[]`：`exerciseId`、`reps`（回数）、`sec`（時間の種目）、`kg`、`bandId`
- `exercises[]`：`name`、`type`（reps / band / time / weight）、`part`（部位）、`nextId`（次の段階）
- `bands[]`：`order` が大きいほど強い
- `skips[]`：休んだ日と理由。`body[]`：体重・ウエスト
- 古い記録に `min` / `max` / `settings.weeklyGoal` が残っていても**使わない**
- **ライン**：各種目の1セット目について、同じ負荷の最近3回の中央値＋1回（時間の種目は＋5秒）。1セット目が **20回以上（時間は60秒以上）** になったら負荷を上げる合図

## 1回の実行でやること（投稿は最大1件）

1. `data.json`、`posts.json`、`topics.json` を読む（`posts.json` / `topics.json` がなければ `[]` とみなす）。`data.json` がなければ何もせず終了
2. 上から順に、最初に当てはまる1つだけを投稿する

| 順 | 種類 `kind` | 条件 | 中身 |
|---|---|---|---|
| 1 | `reply` | `toCoach: true` で、まだ返信していないメモがある（返信済みかは `posts.json` の reply の `ref` で判定） | 未返信のメモを**全部まとめて1件**。最新のメモを `quote` に入れ、`ref` に対象 session の id の配列を入れる。要点を1つ返す（2〜4文）。質問で返して会話の義務を作らない。疲労や気分の原因など、データから分からないことは断定しない |
| 2 | `weekly` | 今日が日曜 | 今週と先週の比較。ライン突破の数、負荷アップ、部位ごとのセット数の偏り、今週の日数。来週やることを具体的に1〜2個（種目名・ライン・バンド名）。2〜4文 |
| 3 | `finding` | 前回の投稿以降に新しい session があり、**伝える価値のある変化**がある | 事実1つとその見方。根拠（日付・種目・数値）を本文に含める。単なる記録の言い換えなら投稿しない |
| 4 | `reading` | 月・水・金（**最後の session から14日以上空いていれば月曜のみ**） | 実際に記録している種目に関係する短い解説（2〜4文）。テーマはフォームの要点、バンド・自重での負荷の上げ方、回復、限界まで追い込む理由と注意のどれか。`topics.json` と要点が重ならないものを選ぶ。**`source`（title と url）を必ず付ける**。信頼できる出典が見つからなければ投稿しない |
| 5 | — | 上のどれにも当てはまらない | 投稿しない |

3. 投稿する場合、`posts.json` の**先頭**に1件追加する（200件を超えたら古いものから削除）
   ```json
   { "id": "2026-10-20-reply", "at": "2026-10-20T07:31:00+09:00", "kind": "reply",
     "quote": "今日は肩が重かった", "ref": ["s_abcd1234"],
     "text": "本文", "source": { "title": "…", "url": "https://…" } }
   ```
   - `id` は `{日付}-{kind}`。同じ id が既にあれば投稿しない（同じ日に二重投稿しない）
   - `reading` を投稿したら `topics.json` に `{ "date", "theme", "point", "source" }` を追加
4. コミットメッセージ `coach: {kind} {日付}`（投稿しない日はコミットしない）で既定ブランチ（main）に push する
5. **最後の返答（Claude アプリの通知に使われる）**
   - reply を投稿した：`コーチから返信が届きました`
   - それ以外：`投稿なし` または `{kind} を1件`（短く）

## 文体
- 「です・ます」は使わず、短く言い切る（例：「1セット目が3回続けて先月の最高を上回っている。負荷を上げる準備ができている」）
- 責めない。休んだこと・記録が少ないことには触れない
- 「久しぶり」「サボり」などの催促や罪悪感につながる表現、日付付きの達成予測は使わない
- 器具は自重とトレーニングバンドが中心。持っていない器具を前提にしない

## してはいけないこと
- `data.json` の変更・削除
- `posts.json` / `topics.json` 以外のファイルの追加・変更
- 失敗したときに、過去の投稿を今日の日付で出し直すこと

# 筋トレ記録アプリ 設計書

日付: 2026-10-19 / 状態: 承認待ち（公開方法まで決定済み）

## 1. 目的と背景

自分専用の筋トレ記録アプリ。Android スマホで、自宅で片手で使う。器具は主に自重とトレーニングバンド（将来ダンベル）。

利用者がこれまで続かなかった理由は2つ：
1. 疲れ・食後・風邪・時間がない等で少しずつやらなくなり、フェードアウトする
2. 成果が見えず、やる気が続かない

だからこのアプリの成功は「記録できること」ではなく **「続くこと」と「成長が見えること」**。全機能はこの2つのどちらかに効く。

「成果」とは、回数・負荷の伸び と 体重・見た目の変化 の両方。

## 2. ゴール / 非ゴール / アンチゴール

**ゴール**
- 種目ごとの回数・負荷・セットの履歴とグラフが見やすい
- 成長（自己ベスト・段階アップ・4週間前比較・累計）を実感できる
- 次回への具体的なアドバイスが出る（ルール判定＋Claude の週次レビュー）
- 種目・バンド・メニューの管理が簡単
- 休憩タイマー、メモ
- 片手で、キーボードをほぼ使わずに記録できる
- 記録が消えない（GitHub 自動保存＋手動書き出し）

**非ゴール（作らない）**
- ログイン、複数ユーザー、SNS、共有
- 食事管理
- 進捗写真の保存（スマホのカメラアプリで撮る前提）
- アプリ内での AI API 呼び出し（無料を優先。理由は §9）
- 複数端末での同時編集

**アンチゴール（動いても失敗）**
- 入力が面倒で、記録すること自体が負担になる
- 休んだ日に責める表示をして、開くのが嫌になる
- 記録データが消える
- 体重の日々の上下をそのまま見せて、やる気を下げる

## 3. 構成（決定事項）

| 項目 | 決定 |
|---|---|
| 形態 | PWA（Android Chrome で「ホーム画面に追加」） |
| 技術 | 素の HTML / CSS / JavaScript（ES modules）。ビルドなし、フレームワークなし、npm 依存なし |
| グラフ | 自前の SVG 折れ線（ライブラリなし） |
| 保存 | `localStorage` に JSON 1つ（キー `kintore:data`）。GitHub 設定は別キー `kintore:github` |
| オフライン | Service Worker で全ファイルをキャッシュ |
| バックアップ | 非公開 GitHub リポジトリへ自動保存＋手動 JSON 書き出し/読み込み |
| AI | ①アプリ内ルール判定 ②「AIに相談」ボタン（コピー＆ChatGPT を開く）③ Claude 定期タスク（週次レビュー＋水曜チェック） |
| 公開 | GitHub Pages（リポジトリを公開、ブランチ main の / (root) から配信）。検索除け：`index.html` に `<meta name="robots" content="noindex, nofollow">` |
| テスト | ロジックは純粋関数にして `node --test`（Node 標準、依存なし） |

ファイル構成（これ以外は作らない）：
```
（リポジトリ直下）
  .nojekyll             Pages の Jekyll 処理を止める（空ファイル）
  index.html            画面の骨組み（4タブ）
  style.css
  app.js                画面描画・イベント・タイマー・同期
  logic.js              純粋関数（判定・集計）。DOM と localStorage に触れない
  logic.test.js         node --test 用
  sw.js                 Service Worker
  manifest.webmanifest
  icon.svg
coach/
  README.md             Claude 定期タスクの手順（§9）
```

`localStorage` の容量（約5MB）で十分：1セット約60バイト、週4回×20セットで10年でも約2.5MB。
`app.js` に `// shortcut: localStorage は約5MB上限、10年分程度で IndexedDB へ移行` を書く。

## 4. データ構造

`kintore:data`（GitHub に同期されるのはこれだけ）：

```js
{
  version: 1,
  updatedAt: "2026-10-19T12:00:00.000Z",   // 保存のたびに更新
  exercises: [{
    id: "e_xxxx",              // "e_" + ランダム8文字
    name: "腕立て伏せ",
    type: "reps",              // "reps" | "band" | "time" | "weight"
    part: "胸",                // "胸"|"背中"|"脚"|"肩"|"腕"|"体幹"|"全身"
    min: 8, max: 15,           // 目標範囲。type=time は秒（初期 20, 60）
    nextId: null,              // 次の段階の種目 id
    archived: false
  }],
  bands: [{ id: "b_xxxx", name: "赤", order: 2, note: "約10kg" }],  // order 小さいほど弱い
  templates: [{ id: "t_xxxx", name: "胸の日", exerciseIds: ["e_..."], sets: 3 }],
  sessions: [{
    id: "s_xxxx",
    date: "2026-10-19",        // 端末のローカル日付
    light: false,              // 軽めの日
    note: "",
    sets: [{ exerciseId: "e_...", reps: 12, sec: null, kg: null, bandId: null }]
  }],
  skips: [{ date: "2026-10-18", reason: "風邪" }],   // "風邪"|"疲れ"|"予定"|"その他"
  body: [{ date: "2026-10-19", kg: 68.2, waist: 80.5 }],  // waist は null 可
  settings: { weeklyGoal: 3, restSec: 90 }
}
```

`kintore:github`（同期しない。トークンを含むため）：
```js
{ owner: "dent052", repo: "kintorekiroku-data", token: "github_pat_...", lastSyncAt: null, dirty: false }
```

- 種目を削除しても過去記録は残す：削除は `archived: true` にするだけ。
- 同じ日付の session は1つ。その日2回目の開始は既存 session に追記する。
- session は**最初のセットを「完了」したとき**に作る（または当日の既存 session に追記）。セットは完了のたびに即 localStorage に保存する。空の session は存在しない。
- 初回起動時（データなし）は種目を空で始め、ホームに「種目を追加」への導線を出す。初期データは入れない。

## 5. 判定ロジック（`logic.js`、すべて純粋関数）

用語：
- **値** = type が reps/band/weight なら `reps`、time なら `sec`
- **負荷** = band なら `bands` の `order`、weight なら `kg`、reps/time はなし（0扱い）
- **その種目の直近 n 回** = その種目を含む session のうち、**今日より前の日付**かつ **light=false** のものを日付降順で n 個（今日の途中経過と軽めの日は判定に使わない）
- **その回の最高値** = その session 内のその種目で、最大の負荷のセットの中での最大値（その回の負荷 = その最大負荷）
- light の session も isPR・totals・compare・weekStats には含める

### 5.1 次回アドバイス `advice(data, exerciseId)`

直近1回のその種目のセット群を見る。上から順に最初に当てはまるもの：

1. **休養**：直近3回（新しい順に s1, s2, s3）の負荷がすべて同じで、最高値が s3 > s2 > s1（2回連続で下がった） → `{kind:"rest", text:"2回続けて下がっています。今日は軽めか休養を"}`
2. **レベルアップ**：全セットの値 ≥ `max` →
   - `nextId` あり → `{kind:"next", text:"次の段階「{次の種目名}」へ"}`
   - type=band でより強い（order が大きい）バンドあり → `{kind:"band", text:"バンドを「{1段強いバンド名}」に"}`
   - type=weight → `{kind:"weight", text:"+1kg に"}`
   - それ以外 → `{kind:"set", text:"セットを1つ増やす"}`
3. **維持**：どれか1セットでも値 < `min` → `{kind:"keep", text:"今の負荷のまま、{min}回を目指す"}`（time は「秒」）
4. **通常**：上記以外 → `{kind:"plus", text:"各セット+1回を目標"}`（time は「+5秒」）

記録がない種目は `null`。

### 5.2 前回値の自動入力 `prefill(data, exerciseId)`
直近1回のその種目のセットの配列をそのまま返す（reps/sec/kg/bandId）。ただし advice が `band` なら bandId を1段強いものに、`weight` なら kg+1 にして返す。`next` のときは前回の値のまま（種目は利用者が切り替える）。記録がなければ 1セット：reps=min / sec=min / kg=5 / bandId=最弱バンド（バンド未登録なら null）。
行数：テンプレートから始めたときは `template.sets` 行、i 行目の値は prefill の `min(i, 長さ-1)` 番目。「前回と同じ」「種目を追加」では prefill の行数。

### 5.3 自己ベスト `prKind(data, set, sessionId)` → `null | "pr" | "load"`
- 初めての種目 → `null`
- 過去（その session 自身は除く全期間）にその種目のどの負荷よりも強い負荷 → `"load"`（負荷アップ）
- 同じ種目・同じ負荷の過去最高値より大きい → `"pr"`
- それ以外 → `null`

### 5.4 段階アップ `isStageUp(data, exerciseId, sessionId)` → boolean
その種目を前の段階（他の種目の `nextId` がこの種目）に持ち、かつその session より前にこの種目の記録がない → true。

### 5.4.1 終了時のまとめ `sessionEvents(data, sessionId)`
`[{ exerciseId, kind: "pr" | "load" | "stage", text }]`。種目ごとに最も上位の1件（stage > load > pr）。text 例：「腕立て 自己ベスト 18回」「バンドロウ 赤→黒」「足上げ腕立て に進んだ」。

### 5.5 週の集計 `weekStats(data, today)`
- 週は月曜始まり。
- `days` = その週に session がある日数（light 含む）
- `achieved` = days ≥ weeklyGoal
- `restWeek` = その週に reason="風邪" の skip がある
- **継続週数** `streak` = 今週を除き、直前の週から遡って `achieved || restWeek` が続く週の数。今週が achieved なら +1。
- `partSets` = その週の部位ごとのセット数

### 5.6 4週間前比較 `compare(data, today)`
- 期間A = 今日を含む直近7日、期間B = 28〜34日前の7日。
- 両期間に記録がある種目ごとに、各期間の最高値と負荷を求める：
  - A の負荷 > B の負荷 → 負荷アップ項目（「バンドロウ 赤→黒」、kg なら「5→6kg」）
  - 負荷が同じ → 最高値の増加率 (A−B)/B。0以下は出さない（「腕立て 最高 12→18回」）
  - A の負荷 < B の負荷 → 出さない
- 並び：負荷アップ項目を先、その後に増加率の大きい順。上位3件。
- 合計回数（time 以外の reps 合計）の増減率（B が0なら出さない）。
- B 期間に session が1つもなければ、比較全体の代わりに「4週間続けるとここに成長が出ます」。
- 体重・ウエスト：各期間の平均の差（両期間に記録がある場合のみ）。

### 5.7 累計 `totals(data)`
種目ごとの reps 合計（time は秒合計）。

### 5.8 体重の表示
グラフは日々の点（薄く）と7日移動平均の線（濃く）。

### 5.9 テスト
`logic.test.js` で最低限：advice の4分岐＋休養（負荷が違うと発動しない）、light と今日の session が除外されること、prefill の band 繰り上げ、prKind（pr・load・初種目）、isStageUp、weekStats の streak（風邪週を挟む）、compare の空期間。

## 6. 画面

下部タブ4つ：**ホーム / トレーニング / 履歴 / 設定**。すべて縦1列、最大幅 480px。

### 6.1 ホーム（開いて最初の画面）
上から：
1. **コーチより**カード：`feedback.json`（§9）の最新。なければ非表示。
2. **今週**：「今週 2/3 日」の進捗と、継続 N 週。月〜日の7マス（やった日=塗り、軽め=半分、休養=斜線）。
3. **4週間前と比べて**：§5.6 の上位3件＋合計回数の増減率＋体重/ウエスト差。データ不足なら「4週間続けるとここに成長が出ます」。
4. **今週の部位別セット数**（横棒）。
5. 画面下部（親指位置）に大ボタン2つ：**「始める」**（テンプレート選択→トレーニング）、**「軽めの日」**。その下に小さく「今日は休む」「体重を記録」。

「今日は休む」→ 理由4択ボタン → skips に保存。責める文言は出さない（例：「休むのも練習。また明日」）。今日 session があればボタンは非表示。同じ日に2回押したら理由を上書き。カレンダーの斜線は理由を問わず全 skip、継続週数を守るのは「風邪」だけ（§5.5）。

「体重を記録」：体重とウエストを −/＋（0.1kg / 0.5cm）で入力、初期値は前回値。初回だけ数字キーボードで入力。ウエストは「なし」にできる。同じ日付は上書き。

### 6.2 トレーニング
- 開始方法：テンプレートを選ぶ / 前回と同じ / 種目を1つずつ追加。
- **軽めの日**：前回の session の種目を、各1セット、light=true で開始。前回がなければテンプレート選択へ。
- 種目ごとのカード：種目名、advice の文言、前回の記録（小さく）、セット行。
- セット行：値の大きな数字と左右に大きな −/＋（reps ±1、sec ±5、kg ±0.5）。band はバンド名のチップを横並びで1タップ選択。「完了」ボタン。
- 値は prefill で埋まった状態から始まる。
- 「完了」で：セット保存 → 自己ベストならその場でバッジ「自己ベスト！」と短いバイブ → **休憩タイマー自動開始**。
- 「セット追加」「種目追加」ボタン。
- 種目に「次の段階へ切り替え」（nextId があるとき）。
- メモ欄：session 単位のメモ（テキスト1つ）。ここだけキーボード使用。
- 「終了」で保存し、その日の成果まとめ（自己ベスト・段階アップの一覧、合計回数）を表示してホームへ。合計回数の「前回より」は増えたときだけ表示する（減った数字は責める表示になるため）。
- トレーニング中は Screen Wake Lock で画面を消さない（非対応端末は無視）。

### 6.3 休憩タイマー
- 画面下部に固定表示の帯：残り秒の大きな数字、−15 / +15、スキップ。
- 初期秒数は `settings.restSec`（初期 90）。
- 終了時 `navigator.vibrate([300,100,300])`。
- 時刻は開始時刻からの差で計算する（バックグラウンドで止まっても正しく復帰するため）。

### 6.4 履歴
- 上部で「種目」「体」「日付」を切替。
- **種目**：種目を選ぶ → 折れ線グラフ（x=日付、y=その日の最高値。負荷が変わった点は色を変え、ラベルにバンド名/kg）→ 下に日付ごとのセット一覧（例「10/19 赤 12・12・10」）、累計、自己ベスト。
- **体**：体重グラフ（§5.8）、ウエストグラフ、記録一覧。
- **日付**：直近12週のカレンダー（§6.1 と同じ記号）。日付タップでその日の内容とメモ。編集できるのはセットの値（−/＋）、セットの削除、メモのみ（日付・light は変更不可）。session 全体の削除は確認ダイアログ付き。

### 6.5 設定
- **種目**：一覧（部位別）、追加・編集（名前、タイプ、部位、目標範囲、次の段階）、アーカイブ。
- **バンド**：追加・名前・メモ・並べ替え（↑↓ボタン）。
- **テンプレート**：名前、種目の選択と並び、セット数。
- **一般**：週の目標日数（1〜7）、休憩秒数。
- **GitHub 保存**：owner / repo / token 入力、「今すぐ保存」「GitHub から復元」、最終保存時刻、未保存の有無。
- **バックアップ**：JSON 書き出し（ダウンロード）、読み込み（確認ダイアログ後に上書き）。
- **AIに相談**：§9.1。

## 8. GitHub 自動保存

- 保存先：非公開リポジトリ `{owner}/{repo}` の `data.json`（ブランチは既定ブランチ）。
- 書き込み：GitHub REST `PUT /repos/{owner}/{repo}/contents/data.json`（本文は `kintore:data` を整形 JSON で base64）。直前に `GET` で `sha` を取得して付ける。
- タイミング：データ変更後 5秒の無操作で送信、`visibilitychange` で hidden になったときも送信。失敗したら `dirty=true` のまま、次回起動時と `online` イベントで再送。
- 片方向（端末→GitHub）。復元は設定の「GitHub から復元」だけ（確認ダイアログ後に上書き）。
  `// shortcut: 単一端末前提で常に上書き。複数端末で使うなら updatedAt 比較を追加`
- コーチの読み込み：起動時とホーム表示時に `GET .../contents/feedback.json` → ホームのカードに表示。失敗時は前回取得分（localStorage `kintore:feedback`）を表示。
- トークン：fine-grained personal access token、対象リポジトリはデータ用1つだけ、権限は Contents: Read and write のみ。設定画面に作成手順へのリンクと1行説明。
- base64 は UTF-8 対応で行う（日本語のため）：`btoa(String.fromCharCode(...new TextEncoder().encode(s)))` は大きい配列で落ちるので、チャンク分割で変換する。

## 9. AI によるフィードバック

### 9.1 「AIに相談」ボタン（手動・無料）
直近28日の session（日付・種目・セット・メモ・light）、skips、body、各種目の目標範囲を、次の前置き付きテキストにしてクリップボードへコピーし、`https://chatgpt.com/` を新しいタブで開く。
前置き：「自宅で自重とバンド中心に筋トレしています。以下の記録を見て、①伸びている点 ②停滞・偏り ③来週の具体的なメニュー提案 を短く教えてください。」

### 9.2 Claude 定期タスク（自動・追加料金なし）
- Claude Code の scheduled task（実行ごとに新しいセッション、対象はデータ用リポジトリ）を2つ作る：
  - **週次レビュー**：毎週日曜 21:00（Asia/Tokyo）
  - **水曜チェック**：毎週水曜 19:00（Asia/Tokyo）
- 指示文は `coach/README.md` に置き、タスクの prompt は「データ用リポジトリの手順に従う」だけにする（指示の正本を1か所に）。※ データ用リポジトリにも同じ `README.md` をコピーして置く。
- **週次レビュー**の出力：`feedback.json` を上書きしてコミット＆push。
  ```json
  { "date": "2026-10-25", "kind": "weekly",
    "summary": "1〜2文",
    "good": ["伸びた点", "..."],
    "next": ["来週やること（具体的に）", "..."] }
  ```
  見る観点：伸び（4週比較）、停滞（§5.1 と同じ基準）、部位の偏り、休んだ理由の傾向、メモに書かれた体調、体重/ウエストの推移。責めない口調。各リスト最大3項目。
- **水曜チェック**：その週（月〜水）に session がなければ `feedback.json` を `kind:"nudge"` で上書き（summary に「軽めの日だけでも」）し、Claude アプリへの通知が出るように終了時の要約にも同じ文を書く。session があれば何もしない。
- 通知：タスクの完了通知（push）を有効にする。

## 10. 実装の進め方

- 実装は Codex（`codex exec`）に、計画書の1タスクずつ渡す。各タスクには、この設計書の該当節と完成条件を明記し、**仕様にない判断が必要になったら実装せずに止まって報告させる**。
- Claude（設計者）が各タスクの差分をレビューし、`node --test` と画面確認（Playwright で 390×844）で検証する。
- コードは最小限（Ponytail）。仕様外の機能・抽象化・設定項目は追加しない。

## 11. 公開（利用者が決定）

- コード用リポジトリ `kintorekiroku` を公開にし、GitHub Pages（main の / (root)）で配信する。記録は別の非公開リポジトリなので公開されない。
- 検索エンジンに載せない：`noindex, nofollow` の meta タグ。`robots.txt` は使わない（Pages のサブパスに置いても効かず、クロールを止めると noindex が読まれないため）。
- リポジトリ自体は GitHub 上で公開なので、GitHub 内の検索では見つかり得る（コードと設計書のみ）。

## 12. 設計者の判断で決めたこと（確認用）

- 技術：素の HTML/JS、ビルドなし、localStorage、自前 SVG グラフ
- 推定 1RM は使わず、最高値・合計・段階アップで成長を測る
- 目標範囲の初期値 8〜15回 / 20〜60秒、週の目標 3日、休憩 90秒
- アドバイスの4分岐と休養判定（§5.1）
- 風邪の週は継続を途切れさせない
- 体重は7日移動平均で表示
- 同期は端末→GitHub の片方向、上書き
- 定期タスクは日曜 21:00 と水曜 19:00
- 初期データ（種目の例）は入れない
- 軽めの日と今日の途中経過は、アドバイス・前回値の判定に使わない（成長の集計には含める）
- 休養判定は直近3回の負荷が同じときだけ
- 4週間比較は「負荷アップ」を最優先、回数が減った種目は表示しない
- 重り種目の初期値 5kg、体重 ±0.1kg・ウエスト ±0.5cm
- 継続週数を守る休み理由は「風邪」だけ
- 過去の記録で編集できるのはセットの値・削除・メモだけ

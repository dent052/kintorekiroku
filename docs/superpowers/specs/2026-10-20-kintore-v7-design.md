# 筋トレ記録アプリ 設計書 v7（記録は実際のとおりに）

日付: 2026-10-20 / 状態: 承認済み（画面イメージ `docs/mockup-v10.html`）
前提: v6 を土台に、**ここに書いたところを置き換える**。それ以外は v6 以前のまま。

## 0. 原則（最優先・利用者の言葉）
「中毒性を高めろって言っただけで記録ゆがめろなんて言ってねえ」。**記録を実際と違う形で見せない・変えない。** グラフは本人の実際の記録で描く。判定は確定した記録だけで、同じ負荷どうしだけ。アプリが負荷や回数を勝手に決めない。

## 1. 記録を正しく残す
### 1.1 負荷を勝手に変えない
- `logic.js` の `prefill`：`line` が `up` でも**前回のセットをそのまま返す**（バンド・重さを上げない）。`logic.test.js` の「prefill upgrades every set from the first-set load…」テストは、この仕様に合わせて**期待値を変えてよい唯一のテスト**（前回の負荷のまま返す、元データを変えない、を確かめる形に）
- 代わりにトレーニングの `.prev` に提案の文字：`line` が `up` のとき `前回{20回／60秒}以上。{next}を検討`（v3 の `lineText(up)` と同じ next の名前）。押すものではない

### 1.2 確定前に判定しない
- 1セット目のカウンタの初期値は **前回の1セット目の実際の値**（`prefill` のまま。v4 §3 の「ラインの値から始める」は廃止）
- v4 の `.lineon`（`ライン{n} 突破`／`あと{d}`）と、確定前の `.over`（朱の数字）は**廃止**。代わりにカウンタの下に `.hint2` `数字を押すと直接入力`
- `.prev` は 1セット目の前 `ライン {値} ・ 1セット目`、確定後は v6 のまま（`突破`／`あと{差}`）

### 1.3 同じ負荷どうしだけ判定
- 1セット目の判定（休憩の帯の上の結果、`.prev`、まとめ、`clearCount`、`feed` の「突破」）は、**その日の1セット目の負荷 = ラインを計算した負荷（`history(...).load`）** のときだけ。違えば判定しない：結果の帯は `新しい負荷` ＋小さく `{バンド名／kg}の1本目`（v3 の newload と同じ文言）、`clearCount` と `feed` は数えない
- `logic.js` に必要なら純粋な関数を足してよい（テストも足す）。既存テストの期待値は §1.1 の1件以外変えない

### 1.4 「ラインは次回へ」をやめる
- 結果の帯の小さな文字：未達のとき `次回のライン {n}`（翌日で `line` を計算した値。突破のときと同じ計算）。値が無ければ出さない

### 1.5 途中の状態を保存
- トレーニングの状態（`training` 全体と、休憩中なら `rest` の終了時刻・長さ）を、変わるたびに `localStorage` の `kintore:training` に保存。起動時に日付が今日なら復元して、ホームの主ボタンは `続きから`（休憩が残っていれば残り時間から）。日付が違えば捨てる。まとめから `ホームへ` で消す

### 1.6 保存の失敗
- `save()` は成功で `true`、失敗で `false` を返す。セットの完了・直す・消す・過去の日の追加で失敗したら、**画面を進めない**（セット数も休憩も変えない）で、トースト `保存できませんでした。もう一度押してください`

## 2. グラフは実際の記録
- 記録の種目画面のグラフ（v6 §4 の階段を置き換え）：横＝日付、縦＝回数（time は秒）
  - **朱の線と点**＝各日の1セット目の実際の値（軽めの日も含む）。**負荷が変わったところで線を切る**（今の負荷の区間は朱、前の負荷の区間は藍）。負荷が変わった最初の点の下に `{バンド名}へ`／`{kg}kgへ`（v3 と同じ）
  - **灰の点**（`#B5BECC`、半径3）＝同じ日の2セット目以降の値
  - 縦軸：左に最大と最小の値の数字（Barlow Condensed 12px `--mute`）と横の細線（`--hair`）。横軸：最初と最後の月
  - 点が1つも無ければ v5 の空の案内
- 数字は `自己ベスト`（今の負荷での全セットの最大値、単位付き）、`前回`（前回の1セット目）、`ライン`（今日の line、無ければ `—`）
- 小さなグラフ `.mini`（ホームの行、記録の一覧の行）：**今の負荷**の最近8日の1セット目の実際の値を、点を結ぶ折れ線（`L`。段にしない）で。上下は最小〜最大（同じなら中央）。2点未満なら空
- `lineHistory` は使わなくなる（消さなくてよい）

## 3. 数字の直接入力
- カウンタの大きな数字（トレーニング、§3 の直すシート、過去の日のセット）と、重さの値（v3 の重さの −／＋ の間の数字）を**押すと**、その場で入力欄（`input`、`inputmode="numeric"`、重さは `inputmode="decimal"`）に変わり、全選択・テンキー表示
- Enter か、ほかを押した（blur）ときに確定。範囲に丸める（reps 0〜200 の整数、sec 0〜600 の整数＝1秒単位、kg 0〜500 で小数1桁まで）。数字でなければ元の値に戻す。Esc で取り消し
- 見た目は見本 `.big input`（重さは見本の重さの行と同じ下線と下地）

## 4. 記録・履歴
### 4.1 日ごと
- 記録のタブの見出しの下に切り替え `.seg`：`種目ごと`（v6 の一覧）／`日ごと`。最後に選んだ方を覚える（`kintore:recordsView`）
- `日ごと`：上に `.pill` `＋ 過去の日を記録`、その下に日の行 `.day`（新しい日が上、セットのある記録・休み・体重だけの日も含む全件）。1行目に日付（900 15px）と小さく `{n}種目`（軽めなら `・軽め`、休みなら `休み`）、その下に種目ごとに `{種目名} {負荷} {セットの値を・でつなぐ}`（time は最後に `秒`）、休みは理由、体重だけの日は `体重 {kg}kg`。右端 `›`。押すと §4.2 の日のシート
- `種目ごと` の `日付から探す` の pill は廃止（日ごとで代わる）。12週間は `種目ごと` に残す

### 4.2 日のシート（v3 の記録の日の編集を置き換え）
- 見出し `{日付}`。種目ごとに小見出し（種目名）と、そのセットの `.row`（v6 §9 と同じ形）。行を押すと同じシートの中で v6 §3 の直す画面（カウンタ、負荷、保存、このセットを消す＋元に戻す）
- 種目ごとの最後に `＋ セット`（前のセットと同じ値で1つ足し、すぐその直す画面へ）
- 最後に `＋ 種目を足す`（種目の一覧から選ぶ→その種目のセットを1つ足して直す画面へ）、メモ、`この日の記録を削除`（v3 と同じ確認あり）
- `＋ 過去の日を記録`：日付を選ぶシート（`input type="date"`、今日より前だけ、既定は昨日）→ `決定` でその日の日のシートを開く（記録が無ければ空。最初のセットを足した時点で session を作る。`light:false`）

### 4.3 体重
- 体重の詳しい画面：v3 の体重のグラフと数字の下に、日ごとの一覧 `.bl`（新しい日が上、日付・値・`›`）。押すとシート：値の直接入力（§3 と同じ）、`保存`、`この日の体重を消す`（確認なし、トーストの `元に戻す` あり）

### 4.4 終了後のまとめ
- `合計回数` と `前回より` と `ライン突破 n / m` を廃止。種目ごとに `.sumrow`：種目名（右端に、その日に自己ベストを更新した種目だけ朱の小さな `自己ベスト`）、今日のセット（負荷付き、time は `秒`）、小さく `前回 {前回のセット}`（無ければ `初回`）

## 5. 見た目
`docs/mockup-v10.html` の CSS をそのまま使う（`.big input` `.hint2` `.seg` `.day` `.chart` `.sumrow` `.bl`）。

## 6. 合格条件
- §0 の原則：確定前に判定・朱が出ない、負荷が勝手に変わらない、グラフの点が実際のセットの値と一致する（e2e で値を照合）
- 閉じて開き直しても続きから、保存失敗で進まない
- 直接入力、日ごと、過去の日、体重の直す・消す、まとめが見本どおり
- `npm test` と `npm run e2e` が通る

## 7. 細部の決定（実装者の質問への答え）
- **ラインが `up`（前回20回／60秒以上）で、今日も同じ負荷のまま1セット目を完了したとき**：数値のラインが無いので「突破／あと」の判定はしない。結果の帯は、前回の1セット目（同じ負荷）との比較を事実として出す：大きな数字＝今日の値、見出し＝上回れば `前回より +{d}`、同じなら `前回と同じ`、下回れば `前回より −{d}`（色は帯の朱のまま。下回っても責める言葉を足さない）。小さな文字＝`{next}を検討`。完了後の `.prev` は `前回{20回／60秒}以上 ・ {next}を検討`。`clearCount`・`feed` は数えない
- 今日の負荷がラインの負荷と違うときは §1.3 のとおり `新しい負荷`（`lineResult(up)` の `newload` もこれと同じ表示）
- 日ごとの行で、同じ日に記録と休みの両方があるとき：小さな文字は `{n}種目・休み`、種目の行のあとに `休み {理由}` の1行

# 筋トレ記録アプリ v2 Implementation Plan

> **For agentic workers:** Execution in this project: each task is handed to Codex (`codex exec`, read-only, outputs whole files) by Claude, who writes them, reviews, runs `node --test` and a Playwright check before the next task. **If anything needs a decision the plan and specs do not make, Codex stops and prints `QUESTION:` (all questions in one block).**

**Goal:** Rework the shipped app per spec v2: "line" mechanic instead of min/max targets, light theme with every action in a bottom dock, one-exercise-at-a-time training, home timeline mixing own-record items with coach posts.

**Architecture:** Same files as v1 (`logic.js` pure + tested, `app.js` UI). No new files. Data stays backward compatible: old `min`/`max`/`weeklyGoal` fields are ignored, never required.

**Specs:** `docs/superpowers/specs/2026-10-19-kintore-v2-design.md` (wins) on top of `docs/superpowers/specs/2026-10-19-kintore-design.md`. Visual reference: `docs/mockup-v4.html` (approved).

## Global Constraints

- Everything in the v1 plan's Global Constraints still applies (`docs/superpowers/plans/2026-10-19-kintore.md`) **except** the color tokens and the defaults for min/max/weeklyGoal, which are removed.
- Color tokens (`:root`): `--bg #F5F6F8` `--surface #FFFFFF` `--fg #111827` `--fg2 #4B5563` `--line #D9DEE5` `--btn #E9ECF1` `--primary #EA580C` `--primary-d #C2410C` `--on #FFFFFF` `--good #15803D` `--good-bg #DCFCE7` `--tip #FFF1E6` `--tip-fg #9A3412` `--danger #B91C1C`. `color-scheme: light`. Theme color in manifest/meta `#F5F6F8`.
- Every tappable control is a button shape: primary = filled `--primary` with `box-shadow: 0 3px 0 var(--primary-d)`; secondary = `--surface` with 2px `--line` border and `0 2px 0 var(--line)` shadow. Non-tappable text/cards never get a shadow.
- **Every action lives in a fixed bottom dock** (`.dock`, above the tab bar) on home, training, history and settings editors. The upper area is display only, except list rows that open something (they look like secondary buttons).
- Copy strings are exactly spec v2 §3.5 / §4.5 / §5. Declines are shown in `--fg2`, never red, never hidden.
- Defaults when no history: reps 10, sec 30, kg 5, weakest band.
- Line constants: up threshold 20 reps / 60 sec; line step +1 rep / +5 sec.
- Keep `node --test` green; every new logic export gets tests.
- CSS: parentheses and braces must balance.

## Review Focus

1. **Old data** — sessions/exercises saved by v1 (with `min`/`max`, `settings.weeklyGoal`) must load and work; nothing may read those fields. Test in Task 1 (fixture with old fields).
2. **Line with mixed loads** — first set on a different load than history must not be compared (H filters by load). Test in Task 1.
3. **Light sessions and today** — never part of H; today's first set is compared against a line computed without today. Test in Task 1.
4. **Posts robustness** — malformed `posts.json` (not an array, items missing `id`/`text`) must not break home; bad items are skipped. Covered in Task 5 by `parsePosts` test.
5. **Badge bound** — unread count shown is `min(unread, 9)`→`9+`, and feed never shows more than 3 items before `すべて見る`. Test in Task 1 (`feed` length) and Task 2 check.

### Task 1: logic.js — lines, stats, feed (replace advice)

**Files:** Modify `logic.js`, `logic.test.js`

**Remove:** `advice`, `compare` and their tests; in `weekStats` the fields `goal`, `achieved`, `streak`; `consultText`'s 【目標範囲】 section (replace by 【負荷アップの目安】 one line `1セット目が20回（時間は60秒）を超えたら負荷を上げる`).

**Produces:**
- `firstSet(data, ex, session) => Set | undefined` — first set of that exercise in the session
- `history(data, exerciseId, today) => {load:number, values:number[]}` — spec v2 §3.1: current load + H (≤3, newest first)
- `line(data, exerciseId, today) => {kind:'base'} | {kind:'up', next:string} | {kind:'line'|'flat'|'down', value:number}` — spec v2 §3.2 exactly. `next`: next-stage exercise name, stronger band name, or `${kg+1}kg`. Median: sort ascending, odd → middle, 2 values → larger.
- `lineResult(l, firstValue) => {kind:'base'} | {kind:'newload'} | {kind:'clear'} | {kind:'short', diff:number}` — §3.3
- `lineText(l, ex) => string` — the pre-set strings of §3.5 (`ライン 16` / `ライン 45秒` / base / up / flat / down; flat and down return their sentence, the app shows the `ライン n` chip separately via `l.value`)
- `prefill(data, exerciseId, today) => Set[]` — §3.4 (replaces v1 behavior; uses `line` kind `up` instead of advice)
- `weekStats(data, today) => {days, partSets, marks}`; `totalDays(data) => number` (distinct session dates)
- `feed(data, today) => {id, at, kind, text}[]` — §5.3, ordered by `at` desc then the kind order clear, pr, load, stage, near. `id` = `${kind}:${exerciseId}:${date}` (near: `near:${exerciseId}:${milestone}`). `at` = session date (near: date of the latest session).
- `mergeFeed(own, posts, seen) => item[]` — own items + posts (`at` ISO string compares with dates by string prefix; use `at.slice(0,10)` for own dates and full `at` for posts), unread `reply` posts first, then by `at` desc. Pure; returns all (UI slices to 3).

**Tests (add, keep the rest):**
- `line`: no history → base; H [14,15,16] (newest first) → `{kind:'line', value:16}` (median 15 + 1); H [12, 15] → 16; time exercise H [40] → 45; latest first set 20 with stronger band → `{kind:'up', next:'黒'}`; latest 22 with `nextId` e4 → next `足上げ腕立て`; six values at same load `[15,15,14, 15,14,13]` (newest first) → flat; H [12,13,14] → down with value 14 (median 13 + 1); first set on band 赤 while H is on 黒 → not counted; light session and today's session ignored.
- `lineResult`: line 16 & 16 → clear; 15 → short diff 1; up → newload; base → base.
- `prefill`: up with band → every set on the stronger band; no history reps → 10; time → 30.
- Old-data fixture: exercise with `min: 8, max: 15` and `settings.weeklyGoal: 3` → `line`, `prefill`, `weekStats`, `feed` work.
- `feed`: returns ≤ 1 item per kind; clear item text `腕立て伏せ ライン16を突破`; near at 95 of 100 → `累計腕立て伏せ 100回まで あと5回`.
- `mergeFeed`: an unread reply older than an own item comes first; a read reply is ordered by time.
- `totalDays`: two sessions same date + one other → 2.
